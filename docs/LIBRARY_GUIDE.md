# AC Library Guide

Every function in every ilib, as of 2026-08-01. This is generated by reading the
actual exported C headers and `.acl` files directly — not from memory, not from
docs that may have drifted. If a library's implementation changes, this file goes
stale exactly like any other doc; verify against the real header before trusting a
signature for anything load-bearing.

Import any library with `use ilib <name>` (or the sub-import form documented under
`web-server`). Call as `<token>.function(args)` — the in-source call token is noted
per library where it differs from the directory name (AC has no kebab-case
identifiers, so a hyphenated directory name always gets a hyphen-free token).

---

## math

`use ilib math` — trig, arithmetic, logs, stats, aggregates, expression eval.
Real implementation on **every backend** (C/C++/PY/JS/GO/RS/JAVA/V/ASM all call
the actual compiled `.so` or native stdlib). Broadest, most mature ilib in AC.

**Constants**: `math.pi`, `math.e`, `math.tau`, `math.em`, `math.phi`, `math.inf`
(each a zero-arg accessor); `math.pi(digits)`, `math.e(digits)`, `math.phi(digits)`
(arbitrary-precision variants).

**Trig**: `sin/cos/tan/csc/sec/cot(x)`, `asin/acos/atan/acsc/asec/acot(x)`,
`atan2(y, x)`, `deg2rad(d)`, `rad2deg(r)`.

**Arithmetic**: `pow(b, e)`, `sqrt(x)`, `cbrt(x)`, `abs(x)`, `abs_int(x)`,
`floor(x)`, `ceil(x)`, `round(x)`, `hypot(a, b)`, `ln(x)`, `log(base, x)`,
`log2(x)`, `log10(x)`, `mod(a, b)`, `mod_int(a, b)`, `to_int(x)`, `to_dec(x)`,
`gcd(a, b)`, `lcm(a, b)`, `is_prime(n)`, `clamp(v, lo, hi)`.

**Aggregates** (array + length): `sigma(arr, len)` (sum), `PI_product(arr, len)`
(product), `gradient(arr, len, out)`.

**Statistics** (array + length): `stat_avg`, `stat_median`, `stat_q1`, `stat_q3`,
`stat_mode`, `stat_min`, `stat_max`, `stat_boxnum(arr, len, out)`.

**Other**: `eval(expr)` — string expression evaluator.

*Known gaps*: `calculus.hpp`/`i.hpp` (derivatives/integrals, complex numbers) are
real, working C++ code but not exported through the C ABI or `.acl` — reachable
only if you write raw C++ against the header directly, not through normal AC
`use ilib math` calls.

## os

`use ilib os` — shell/filesystem access. Real on every backend it targets
(C/C++/PY/JS/GO/RS/JAVA/V — no HTML, sensibly, no ASM/BNY-specific shim).

`os.bash(cmd)` — run `cmd` via a real shell, unrestricted, by design (full
shell freedom is the point of this one).
`os.sbash(cmd)` — same, but rejects a **denylist** of dangerous substrings
(`sudo`, `nohup`, `tmux`, `screen`, backgrounding `&`, etc.) before running. This is
an accident-guard, not a sandbox — it stops honest mistakes (a script that
accidentally tries to background/persist/escalate), not a determined bypass
(`;`, `|`, backticks, `$()` aren't blocked). Judge it as a guardrail, not a security
boundary.
`os.app_open(app)`, `os.mkfile(path)`, `os.rmfile(path)`, `os.mkdir(path)`,
`os.rmdir(path)`, `os.exists(path)`, `os.cwd()`, `os.env(key)`,
`os.write_to(path, content)`, `os.append_to(path, content)`, `os.read(path)`.

*Known gap*: Java's `chdir` equivalent is a no-op (spawns a subprocess to run `cd`,
which structurally can't affect the parent JVM's working directory) — fixing it for
real means tracking a working-directory string in Java-side state and prefixing
every path op with it, not a one-line patch.

## regex

`use ilib regex` — real regex engine per backend (`std::regex`/`re`/`RegExp`/
`Pattern`/etc., or FFI to `libacregex.so`). Fixed this session: `regex_ffi.rs` had
genuinely invalid Rust syntax (`let cs, cp, cr = ...` — not legal without tuple
destructuring) blocking `replace`/`replace_all` on Rust; now compiles clean.

`regex.match(str, pat)`, `regex.test(str, pat)` — predicates (1/0).
`regex.search(str, pat)`, `regex.replace(str, pat, repl)`,
`regex.replace_all(str, pat, repl)`, `regex.escape(str)` — string results.
`regex.count(str, pat)` — integer result.
`regex.find_all(str, pat)`, `regex.split(str, pat)`, `regex.groups(str, pat)` —
list results (heap-allocated internally, freed automatically by the FFI wrapper).

## string-cheese

`use ilib string-cheese`, call token `stringm`. String manipulation, real on
C/C++/PY/JS/GO/RS/JAVA/V.

`stringm.upper(s)`, `stringm.lower(s)`, `stringm.trim(s)`, `stringm.strip(s)`,
`stringm.find(s, pattern)`, `stringm.replace(s, old, new)`,
`stringm.split_nth(s, sep, n)`, `stringm.length(s)`, `stringm.startswith(s, prefix)`,
`stringm.endswith(s, suffix)`, `stringm.count(s, sub)`,
`stringm.format(template)`/`stringm.f(s)`/`stringm.t(s)` — f-string/t-string
interpolation, resolved at the IR level, `stringm.b(s)` — bytes view,
`stringm.endian(bytes, order)` — bytes → int ("little"/"big"),
`stringm.getline()` — read a line from stdin, `stringm.scan(needle)` — read a line
and check if it contains `needle`, `stringm.ischar(s)`/`stringm.isws(s)` — character
class checks.

*Known gaps*: Go's `getline`/`scan` are literal stubs (`return ""`/`return false`,
commented "stub for now" — never actually read stdin). Rust and V are missing
`endian`/`b`/`f`/`t`/`getline`/`scan`/`ischar`/`isws` outright (not stubbed, just
absent from those two FFI files). The `.acl` also references a plain `stringm.split`
and `stringm.join` that don't exist in the C core (only `split_nth` does; `join` is
native-only in PY/JS/Java) — treat the `.acl` as slightly ahead of what's actually
wired for those two names.

## web

`use ilib web` — client-only: open links/files, fetch a page. Real on every
backend (PY/JS/HTML/C/CPP/GO/RS/JAVA/V/ASM/BNY).

`web.open(link)` — opens `https://{link}`. `web.file_open(file)` — opens
`file://{file}`. `web.popen(raw_link)` — opens the link exactly as given, no
prefixing. `web.ropen(search)` — opens `https://{search}.com`.
`web.browser()` — opens the default browser to Google.
`web.pdf(pdf)`/`web.text(text)`/`web.inspect(program)` — open a file if its
extension matches (pdf; txt/md/bashrc/zshrc; common source extensions) — return
1/0 for whether it actually opened.
`web.ac_page()` — opens the AC language website.
`web.page_get(url)` — HTTP GET, returns the body as a string (adds `https://` if no
scheme, 15s timeout, `""` on any error).
`web.help()` — prints this list.

*Security note*: `page_get` validates the URL and blocks shell metacharacters before
ever touching a subprocess. The other open-a-link functions historically did not
apply the same validation on every backend — fixed this session for the C and V
FFI (now use `execvp`/argv-array instead of `system()`), and the JS Node fallback
for `page_get` (now `execFileSync` with an argv array instead of a
`JSON.stringify`-escaped shell string, which only escapes for JSON, not shell).

## web-server

`use ilib web-server`, or the sub-import form: `from ilib web use web-server`
(these are equivalent — `web-server` is a companion library to `web`, importing one
never pulls in the other). Call token: **`server`**. HTTP serving + SQL, added this
session, all 9 real backends (PY/JS/C/CPP/GO/RS/JAVA/V/BNY) runtime-verified;
ASM has the dlopen shim written but untested (lowest priority).

**HTTP** (singleton state — one listener, one "current request", one request in
flight at a time, no threads):
`server.listen(port)`, `server.accept()` (blocks for the next request),
`server.req_method()`, `server.req_path()`, `server.req_query(key)`,
`server.req_body()`, `server.req_header(name)`,
`server.respond(status, body)`, `server.respond_json(status, json_body)`,
`server.close()`.

**SQL** (via a vendored JaSQL/AbuDB engine, run in a persistent worker process —
not spawned per query):
`server.db_run(statement)` — no placeholders, trusted/static text only.
`server.db_run_p(statement, paramsJson)` — `?`/`:name` placeholders, bound
server-side by JaSQL's own parameter binding (JSON array or object string for
`paramsJson`) — **the only safe path for any query built from request-derived
data**; `db_run` never string-concatenates anything itself, by construction.
`server.db_import(path)` — `.datac`/`.csv`/`.xlsx` by extension.
`server.db_reset()`, `server.db_stop()`, `server.help()`.

*Known gap*: a **bare, uncaptured** multi-arg call (e.g. `server.respond(200, ...)`
with no `z = ` assignment) doesn't complete correctly on BNY — always capture the
return value into a variable.

## gl

`use ilib gl` — SDL2 2D game/GUI engine: windows, objects with physics-ish
velocity/collision, draw primitives, keyboard input, frame loop. Real, substantial
implementation (real event polling, AABB collision, a hand-rolled expression
evaluator for curve trajectories) — not a toy. Fixed this session: `gl_ffi.rs`
declared its `extern "C"` block under the wrong symbol names entirely
(`_raw_ac_gl_*` vs the real exported `ac_gl_*`) — added `#[link_name]` attributes,
verified linking + running against the real `.so`.

**Init/screen**: `gl.init()`, `gl.quit()`, `gl.screen_create(w, h, title)`,
`gl.screen_set_bg(r, g, b)`, `gl.screen_set_fps(fps)`, `gl.screen_w()`,
`gl.screen_h()`, plus higher-level helpers `gl.screen_init(w, h, title)` (init+create
combined), `gl.screen_animate(fps_spec)` (e.g. `"60fps"`),
`gl.screen_set_bg_by_name(color_name)`.

**Objects** (named, have position/color/velocity — full game-object properties):
`gl.obj_create(name)`, `gl.obj_geometry(name, w, h)`, `gl.obj_square(name, size)`,
`gl.obj_pos(name, x, y)`, `gl.obj_color(name, r, g, b)`,
`gl.obj_color_by_name(name, color_name)`, `gl.obj_velocity(name, vx, vy)`,
`gl.obj_set_speed(name, speed)`, `gl.obj_set_direction(name, deg)`,
`gl.obj_speed_mult(name, mult)`, `gl.obj_move_x/move_y(name, delta)`,
`gl.obj_x/obj_y/obj_w/obj_h(name)`, `gl.obj_pos_from_spec(name, x_spec, y_spec)`
(e.g. `"center"`, `"screen-50"`), `gl.obj_config_item(name, item_spec)` (e.g.
`"square(50)"`).

**Trajectory/animation**: `gl.obj_curveshape(name, expr)`, `gl.obj_vertex(name, vx, vy)`,
`gl.obj_circle_fall(name, fraction, dir)`, `gl.obj_circle_fell(name, fraction, dir)`,
`gl.obj_animate(name, dir, speed)`.

**Spawn**: `gl.obj_set_spawn(name)`, `gl.obj_save_spawn(name)`, `gl.obj_regen(name)`.

**Draw type** (pure geometry, no object properties): `gl.draw_create(name)`,
`gl.draw_curveshape`, `gl.draw_vertex`, `gl.draw_line(name, x1,y1,x2,y2, r,g,b)`,
`gl.draw_circle(name, cx,cy,radius, r,g,b)`, `gl.draw_clear(name)`.
Convert between object/draw: `gl.obj_to_draw(name)`, `gl.draw_to_obj(name)`,
`gl.is_draw(name)`, `gl.is_obj(name)`.

**Collision**: `gl.hitbox_overlap(a, b)`, `gl.hitbox_overlap_boundary(name)` (touches
screen edge), `gl.hitbox_overlap_pattern(name, pattern)` (wildcard match, e.g.
`"p%"`), `gl.hitbox_many_overlap()`.

**Input**: `gl.key_pressed(key)` (held this frame), `gl.key_just_pressed(key)`
(pressed this frame only) — key names are plain strings ("w","a","up","space",
"enter","escape", etc.), handled entirely inside `gl`'s own SDL2 event loop —
**not** currently connected to the `keybinds`/`configure event-listener` system
described below (`gl` reads keys directly; `event-listener` is a separate,
JS/HTML-only mechanism today).

**Frame loop**: `gl.frame_begin()` (poll events, returns 0 when window closes),
`gl.frame_update(dt)`, `gl.frame_render()`, `gl.frame_end()`, `gl.delta_time()`.

*Known gap*: `obj_circle_fall`'s `dir` parameter is accepted but ignored — only
rightward fall is currently implemented.

## camera

`use ilib camera` — OpenCV webcam capture + a GTK-independent "sidebar console"
(text overlay/prompt) + basic screen mode control. Real, OpenCV-backed on
C/C++/PY/JS/GO/RS/JAVA/V. Fixed this session: `ask()`/`getInput()` were

`camera.init()`, `camera.capture(filename)`, `camera.capture_latest()`,

`sidebar.config(...)`, `sidebar.setregion(...)`, `sidebar.setinteractive(bool)`,
`sidebar.display(msg)`, `sidebar.ask(prompt)` (blocks for input, now correctly
returns it), `sidebar.getinput()` (same, no prompt).
`screen.setmode(...)`, `screen.update()`.

## machine-audio

`use ilib machine-audio`, call token **`maudio`**. Text-to-speech + MP3 playback +
white noise. Real, functional on PY/JS/GO/RS/JAVA/V/C/CPP (shells out to
espeak-ng/say/aplay, or calls the compiled `.so`).

`maudio.say(text)`, `maudio.construct(text)`, `maudio.voice(gender)` ("male"/
"female"), `maudio.rate(percent)` (0-200), `maudio.pitch(percent)` (0-100),
`maudio.amplitude(percent)` (0-200).
`maudio.load_mp3(path)` → track handle, `maudio.play(handle)`,
`maudio.play_loop(handle)`, `maudio.pause(handle)`, `maudio.stop(handle)`,
`maudio.reverb(handle, percent)`, `maudio.speed(handle, percent)`,
`maudio.decode(handle)`, `maudio.free(handle)`.
`maudio.static_noise(duration_ms)`.

*Known gaps*: `reverb`/`speed` are stored on the track but never actually read
during playback (silent no-op). No way to resume after `pause()`. Command
injection in the `.hpp`/JS/V shell-string-building for `speak`/`listen` — fixed
this session (argv-array `execvp`/`execFileSync`/V process API instead of raw
shell-string interpolation).

confusing situation where the same nominal API is functional in one Python path and
faked in the ctypes/GTK path every other language uses.) ASM FFI only has `extern`
declarations, no callable functions — non-functional. JS/HTML variant is missing
roughly 11 widget types the other backends have.

## ml

`use ilib ml` — tensor math + autograd, aiming for a PyTorch/TensorFlow-style
surface across backends.

**Real, working core** (genuine reverse-mode autograd):
`ml.tensor(value)`, `ml.grid(rows, cols, fill)`, `ml.gradient_track(id, enabled)`,
`ml.grad_wipe(id)`, `ml.weights(learning_rate, id)`, `ml.take(id)` (read the
scalar value out), `ml.add(a, b)`, `ml.multiply(a, b)`, `ml.relu(x)`,
`ml.backward(loss)`, `ml.grad(id)` (get gradient).

**PyTorch-style tensor ops** — real, but no autograd hookup (no backward-pass
registered for these specifically): `pt_tensor_from_data(...)`, `pt_randn(...)`,
`pt_zeros(...)`, `pt_ones(...)`, `pt_tensor_shape(...)`, `pt_tensor_dtype(id)`,
`pt_tensor_to_array(...)`, `pt_matmul(a, b)`, `pt_add(a, b)`, `pt_multiply(a, b)`,
`pt_relu(x)`, `pt_softmax(x, dim)`, `pt_reshape(...)`, `pt_to_device(x, device)`,
`pt_tensor_free(x)`.

**TensorFlow-style** — mostly stub: `tf_constant(...)` and `tf_variable(...)` and
`tf_matmul`/`tf_nn_relu`/`tf_nn_softmax` are real; `tf_losses_sparse_categorical_
crossentropy` just returns `y_pred` unchanged (not a real loss computation).

**Optimizers**: `ml_sgd_step(lr, id)` is real. `ml_adam_step(lr, beta1, beta2,
epsilon, id)` silently discards beta1/beta2/epsilon and calls plain SGD instead —
not actually Adam.

**Model utilities — all stub**: `ml_model_new()`, `ml_model_add_dense(...)`,
`ml_model_forward(...)` are no-ops/constants, not a real layer system.

**Data loading — all stub**: `ml_load_csv(...)` and `ml_train_test_split(...)`
return -1/error unconditionally. `ml_normalize(x)`/`ml_one_hot(y, n)` are identity
functions (pass input through unchanged) — not real normalization/encoding.

**Utility**: `ml_tensor_print(x)`, `ml_version()`, `ml_init()`, `ml_cleanup()`.

*Known gaps*: everything under "Model utilities" and "Data loading" above is a
silent no-op dressed up as a real function — the biggest "looks complete, isn't"
gap found in the whole audit. JS/Java are independent toy reimplementations, not
bound to the real core at all. A separate `LibACML.java` (richer, JNI-based API)
needs a native `libacml_jni` that doesn't exist anywhere in the repo — dead,
unbuildable code, distinct from the working `ml_ffi.java`.

## aczip

`use ilib aczip` — file compression/archiving. Genuinely good, hardened C++ core
(parallel zlib compression, thread pool, zip-slip-safe extraction). Fixed this
session: the `.so` only ever exported C++-mangled symbols while Go/Rust/V/Java/ASM
all expected 6 plain-C symbols that didn't exist — added a proper `extern "C"`
shim (`aczip_c.h`/`aczip_c.cpp`, following the same pattern as `camera_c.cpp`),
a `.acl` (there wasn't one), and a `Makefile` target to build `libaczip.so`/`.a`
from both files together. Verified with real link+run tests on Go, Rust, V, and
Java (full compress/decompress round trips); ASM now assembles with all 6 symbols
resolvable.

`aczip.compress(path, parallel)` → a `{data, size}` byte buffer (heap-allocated —
release it with `aczip.free_bytes(...)` when done; returns `{NULL, 0}` on
failure). `aczip.decompress(data, size, output_path)` → 0 on success. Two
tuned variants: `aczip.compress_hdd(path)` (sequential, less random access) and
`aczip.compress_sata(path)` (balanced, threaded).
`aczip.get_compression_ratio(original, compressed)` → percentage.
`aczip.free_bytes(buffer)` — release a buffer from any of the `compress*` calls
(safe to call on a `{NULL,0}` result).

Also fixed this session: real command-injection bugs in `ACTar`/`ACXz`/`ACZstd`'s
shell-string-building for `xz`/`tar`/`zstd` subprocess calls in both `aczip.cpp`
and `aczip.js` — now argv-array `execvp`/`execFileSync`, no shell. Two incidental
bugs found and fixed in `ffi/ACZip.java` along the way (a missing
`Structure.ByValue` on the JNA struct-by-value return type, which segfaulted
without it, and unqualified references needing `ACZipLib.` qualification).

*Known gaps*: PY and JS's `ACZip` class (as opposed to `ACXz`/`ACZstd`, which got
the injection fix) bypass the compiled core entirely and use an OLDER, different
archive format (loses filenames, can race, can div-by-zero per the C++ code's own
comments about what was fixed in the newer format) — migrating them onto the same
format as everyone else is a separate, larger task. `aczip_ffi.v` itself has
pre-existing V-syntax incompatible with the installed V 0.5.1 (`!void` return
type, byte-slicing syntax) — unrelated to the symbol-linking fix, not touched.
`ACZip::build_archive`'s path handling only strips a leading `/` rather than
computing a true relative path, so archives of absolute paths embed more path
structure than expected (functionally harmless — zip-slip protection is
unaffected — but worth a separate look).

## keybinds

Not a traditional ilib — pure per-language `KEY_<NAME>` constant tables, no C core.
Purpose: a shared key-name bridge for `configure event-listener` / `on value is
<key>` (AC syntax that binds a callback to a named key). The AC-source key name
(e.g. `space`) has to be translated to whatever value that backend's *real*
key-event system reports — very few of them literally match the AC name (the
browser's `KeyboardEvent.key` for the spacebar is `" "`, not `"space"`;
`java.awt.event.KeyEvent` uses numeric `VK_*` codes).

Fixed this session: `keybinds.js`'s own values were wrong for this purpose
(`KEY_SPACE = "space"`, should be `" "`; also `TAB`/`SHIFT`/`CTRL`/`ALT`/`SUPER`/
arrows/brackets all wrong), plus a duplicate `KEY_ENTER` declaration breaking
compilation in 6 of its 6 language files. All 6 files (`py`/`js`/`go`/`rs`/`java`/
`v`) now have exactly one `KEY_ENTER`, and bracket values corrected to the
unshifted key (`[`/`]`, not `{`/`}`) everywhere. Java's values were already correct
(real `java.awt.event.KeyEvent.VK_*`).

**Wired into the compiler** (this session, `ir_codegen.cpp`): only for JS/HTML,
the only two backends with a *real* OS-level key hook
(`document.addEventListener('keydown', ...)`). `loadJsKeybindsTable()` reads
`keybinds.js` once; `translateJsKeyConstant()` looks up the AC key name before
emitting the comparison in `emitEventBind`/`emitEventTrigger`, falling back to the
raw AC text for anything not in the table. Verified: `on value is space` now
compiles to comparing against `" "`, not `"space"`.

**Not wired**: Python (no live OS hook exists to normalize against — bind and
trigger are both driven by AC source text matching itself, so it's self-consistent
without translation). `gl`/`widgets` don't implement `event-listener` at all —
every backend's `emitEventBind` other than PY/JS/HTML is a silent no-op in the
compiler's base class. Wiring real keyboard events for `gl` (SDL2 scancodes) or
`widgets` (GTK keyvals) means giving those backends' codegen a real
`emitEventBind` implementation for the first time — a feature addition, not a bug
fix, and a real next step if `configure event-listener` is meant to work with
compiled (not just JS/HTML) game/GUI programs.

*(Renamed from `pointers` and fully rebuilt 2026-08-01, per `docs/NATIVE_CPU_SPEC.md`.
The old `pointers` library was, in practice, broken on every backend except
Python — bare `ptr_new`/`ptr_deref`/... calls never matched any FFI file's
actual exported symbol names on C/CPP (missing headers entirely), Go (exported
`PtNew` not `ptr_new`), Rust (depended on the unavailable `lazy_static` crate —
never compiled), V (used a receiver/struct-naming syntax the installed V 0.5.1
rejects), Java (FFI filename didn't match the `<lib>_ffi.<ext>` convention the
compiler looks for, so it was never even loaded), and BNY (dispatch code
checked for a LIB_CALL method string that never gets constructed for bare
calls, and called undefined helper labels even if it had matched). All of this
is fixed now, verified end-to-end with the real toolchain per language.*

Directory: `library/ilib/native-cpu/`. Call convention is **mixed by design**,
matching the spec: the 7 carried-over pointer functions are called **bare**
(`ptr_new(...)`, not `ncpu.ptr_new(...)`) exactly as before; every new function
is called **dotted** (`ncpu.dha(...)`, `ncpu.abort()`, ...), the same convention
`os.`/`ml.`/`regex.`/`stringm.` already use.

**Pointer registry (bare, carried over):**
`ptr_new(value, size, type_id)`, `ptr_deref(ptr)`, `ptr_null()`,
`ptr_is_null(ptr)`, `ptr_eq(a, b)`, `ptr_copy(ptr)`, `ptr_update(ptr, value)`.

**Allocation:** `ncpu.dha(size)` (malloc-style), `ncpu.zdha(size)`
(calloc-style, zeroed), `ncpu.realloc(ptr, size)`, `ncpu.bmdha(size)` /
`ncpu.bmzdha(size)` (bare-metal — real anonymous `mmap`, bypassing the libc
allocator entirely; on Python/JS this is best-effort since those hosts have no
raw-mmap-vs-heap distinction that matters — documented, not faked),
`ncpu.bmrealloc(ptr, size)`.

**Arena allocator (bump allocator, bulk free):** `ncpu.arena_create(size)`,
`ncpu.arena_alloc(arena, size)`, `ncpu.arena_dealloc(arena, ptr)` (a documented
no-op — bump allocators don't free individual items), `ncpu.arena_destroy(arena)`,
`ncpu.arena_abort(arena)` (O(1) bulk reset, keeps the buffer for reuse).

**Control:** `ncpu.abort()` — a real hard abort (`std::abort()`/`os.abort()`/
`process.abort()`/`SIGABRT` per language), not a clean exit. On BNY it goes
through the same dynamic-linking path as everything else here (no hand-written
`ud2` trap — scoped out this pass).

**Messaging (between quickthreads):** `ncpu.broadcast(msg)` / `ncpu.recieve(msg)`
(spelling is intentional) — a process-global, mutex-guarded named-message set;
`recieve` checks-and-consumes.

**Architecture per backend:** Python/JS are native reimplementations (per the
usual rule). C/C++ `#include` `native-cpu.hpp`/`native-cpu_c.h` and link
`libacncpu.so` (built from `native-cpu.cpp`). Go/V/Java link the same `.so` via
cgo/C-interop/Panama FFI respectively. Rust and BNY do NOT link the `.so` —
Rust is a from-scratch native reimplementation (real `mmap`/`munmap` via raw
`extern "C"` declarations, no external crate); BNY resolves every `ncpu.*` call
(and the bare `ptr_*` ones) through its existing PLT/GOT dynamic-symbol
mechanism against `libacncpu.so`, same as `os.`/`regex.`/`ml.` already do.

**Known gaps, explicitly deferred, not silently skipped:**
- The `atomic` type keyword (spec: `atomic s = 5`) is **not implemented**. The
  spec itself says its semantics are author-TBD, and wiring a new type
  through lexer/parser/`type.hpp`/every backend is comparable in size to how
  `short`/`mini` were added — a separate project, not bundled into this pass.
- BNY's `ncpu.abort()` reuses the dynamic-link path rather than emitting a
  literal `ud2` trap instruction — a real, fitting BNY-native implementation,
  but scoped out to keep this pass bounded.
- Java's bare `ptr_new`/`ptr_deref`/etc. calls **do not resolve** — a
  pre-existing Java-codegen architecture gap (ilib FFI content is injected as a
  *separate* top-level class; Java has no free functions, so an unqualified
  call can't reach another class's static method without a compiler-side
  rewrite). The new dotted `ncpu.*` surface works correctly on Java; only the
  7 carried-over bare functions are affected, exactly as before this rename —
  not made worse, but not fixed either, since the fix is a Java-codegen change
  affecting every ilib, not something scoped to this library.
